# Web pm-AMM implementation plan

The web app will use PREDICT binary markets on devnet. Native clients and their server routes remain unchanged. Creator signing stays on the operator machine.

## Implementation plan

1. M1: pin root SDK dependencies; implement shared spec validation, deterministic names, fee-aware quotes, positions and strict multi-day NOAA evaluation. Add guarded operator creation, resolution and creator redemption scripts, public catalog/evidence and measured liquidity notes. Create upcoming markets and a historical mechanics demo, recording signatures and any external blockers. Run focused tests and existing checks, request a fresh-context read-only implementation/code review, fix findings and commit.
2. M2: route `/app` and subroutes to the Vite client; remove Expo from site builds. Add market list, reviewed swaps with fresh quotes, positions, Collect and public settlement verification. Update web tests; review, fix and commit.
3. M3: copy the official burner kit with source attribution, integrate automatic devnet funding and recovery controls, retain Phantom. Review, fix and commit.
4. M4: record both root audits, address high/critical findings where compatible, verify the site build and preview, mocked browser tests and shared-code real-devnet trade. Save screenshots and operating instructions; review, fix and commit.

Normal trading ends no later than midnight at the start of the station-local observation window. Resolution waits for a complete, unflagged NOAA record for every inclusive day. A separately marked historical mechanics demo is the only exception to the pre-observation trading rule. No substitute station is selected after trading.

The owner authorized implementation and fixes without intermediate approval gates. Each milestone receives a fresh-context EGM implementation-readiness/code review. Reports and fixes go in REVIEW.md. Work stops at the last working milestone if external blockers prevent completion.

## File boundaries and acceptance details

M1: `shared/pm-amm/spec.ts` exports `MarketSpec` (station/name/city/timeZone, inclusive start/end, integer thresholdTenths, endTs, historicalDemo), date validation, station midnight conversion, deterministic name and catalog identity assertion. `noaa.ts` exports a strict evaluator and Evidence type; each record retains raw response/hash, per-day tenths, sum, threshold, outcome and resolve signature. `helpers.ts` is the official helper copy. `trading.ts` exposes raw amount validation, fee-aware buy/sell quote with minimum, payout and estimated mark value. Operator modules in `scripts/pm-amm/` own external key reads, catalog/run writes, guarded create/trade/resolve/Collect and LP redemption. Persistent attempts prohibit retries after uncertainty. Resolution evidence is immutable once a send is attempted. Tests assert date ordering, local day boundaries/DST, catalog tamper refusal, inclusive rainfall boundary, dry/missing/duplicate/flagged/malformed/overflow input, buy/sell units/fee/minimum and evidence structure. Finalized transaction token receipts prove actual settlement.

M2: add `client/src/pages/pm-amm.tsx` and `client/src/lib/pm-amm.ts`, using the shared catalog/helper/math. `App.tsx` mounts `/app/*` and redirects legacy `/preview` to `/app`. Existing server/API and native files stay intact. Root build scripts omit Expo, Vercel and local preview serve the Vite index for app subroutes. The UI polls batched chain state no faster than every 15 seconds, pauses while hidden, and refreshes after sends. Quotes show gross input, fee, net shares and 1% minimum; confirmation fetches state again and requires another review when the quote changes. Positions read associated YES/NO accounts; unresolved marks say estimate and expired markets cannot swap. Collect requires chain resolution and positive winning balance. Verification reads committed evidence and links NOAA plus devnet resolution/redemption receipts. Browser tests mock RPC account bytes, verify deep links, both quote directions, stale quote rereview, errors, positions/Collect, verification links and phone overflow. No fixture data enters production code.

M3: official `burner.ts` and `useBurnerWallet.ts` under `client/src/lib/pm-burner/`, copied verbatim with attribution. Existing Vite Buffer shim remains. A wrapper catches failed wallet setup, displays funding errors, and offers explicit export/new-wallet controls with loss warning and a devnet-only notice. Export must be an explicit click; never log secret material. Keep Phantom through wallet-adapter and an Anchor provider on the same hardcoded devnet connection; active signer changes clear pending review. Tests mock faucet success/refusal and wallet errors, ensure no auto-loop on rate limits and clear stale positions on identity change.

M4: `docs/pm-amm-web/audit.md` records root production/full audit counts and unresolved dependency paths. Prefer compatible patches/overrides; do not alter native dependency manifests. Run all owner-listed checks, site build, local preview and shared-code real devnet quote/buy. Save markets/review/positions/verification screenshots in `shots/`; README records the final architecture, operation, trusted resolver/missing-data limits, transactions and outstanding work. Audit `git diff` for native/Anchor/API mutations and accidental secrets before final commit.
