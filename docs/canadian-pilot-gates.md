# Canadian rainfall pilot release gates

Saskatoon (low rainfall over five full UTC days) and Toronto (at least 1 mm over one full Toronto local calendar day) are **research targets**, not active Devnet contracts. SkyHedge must not display a payable quote or prepare a transaction for either city until all gates below pass and the admin signs finalized create, fund, and open transactions.

The [NOAA GHCN-Daily station list](https://www.ncei.noaa.gov/pub/data/ghcn/daily/ghcnd-stations.txt) identifies nearby stations, but a station name is not evidence coverage. The [PRCP inventory](https://www.ncei.noaa.gov/pub/data/ghcn/daily/ghcnd-inventory.txt) shows that the originally considered `CAN04057120` (Saskatoon Diefenbaker airport) ends in **2009**, and `CAN06158350` (Toronto) ends in **2017**. Neither is suitable as the current/recent rainfall source for these pilots. They are not pinned in the catalog or on-chain.

Read-only NOAA audit on 2026-10-04 found these **replacement research candidates**, not validated settlement stations:

The repository's `auditGhcndRainfallWindows` helper parses NOAA's [fixed-width GHCN-Daily format](https://www.ncei.noaa.gov/pub/data/ghcn/daily/readme.txt), requires each requested PRCP date, rejects missing/quality-flagged/trace values, and hashes the examined values. This is a historical-data screening tool, **not** proof of forecast coverage, station suitability, final NOAA settlement data, or commercial-use permission.

Before activation, the operator must document:

1. Confirmed rights to use and distribute the chosen Canadian station data and derived values for this service. [NOAA's GHCN-Daily documentation](https://www.ncei.noaa.gov/pub/data/cdo/documentation/GHCND_documentation.pdf) warns that some non-U.S. contributions have commercial-use/re-export restrictions. Until rights are confirmed, the release gate is closed.
2. Ten analogous historical windows with every required rainfall value present, acceptable quality flags, station identity, and exact time boundaries. Saskatoon's proposed trigger is the second-lowest of those ten observed totals, shown for admin review rather than silently activated.
3. For Toronto, complete [GHCNh hourly](https://www.ncei.noaa.gov/products/global-historical-climatology-network-hourly) precipitation intervals for the full local day. A GHCN-Daily or synoptic daily total alone cannot be assumed to equal a Toronto midnight-to-midnight calendar day. Daylight-saving transition days may be 23 or 25 hours.
4. A [NOAA GFS](https://www.nco.ncep.noaa.gov/pmb/products/gfs/) forecast whose precipitation intervals cover the exact immutable window, with no gaps, overlaps, partial periods, or presumed zero values. The deterministic forecast trigger component is labeled a **trigger signal**, not a calibrated probability.
5. Separate Canadian methodology and source hashes over the actual NOAA inputs, plus a validated station and data-rights record. Revalidate all inputs immediately before preparing admin transactions.
6. Finalized program, IDL, protocol, market, and 2,000-SKYT vault state. A market is not available merely because it appears in search or the AI guide.

The code currently implements exact Saskatoon/Toronto time-window helpers, a fail-closed check for decoded forecast-interval coverage, an activation gate, and research-only guide behavior. The interval check rejects forecasts that cross an immutable window boundary; it does **not** prove that the values came from NOAA. A Toronto local midnight can fall between coarser GFS precipitation intervals, so that contract remains blocked unless an actual forecast product covers its exact UTC start and end without interpolation. The code does **not** claim a complete Canadian NOAA adapter, validated station package, licensed feed, funded market, or working Canadian payout.

The public AI guide is also not a release-ready paid service until its server-side Anthropic key is configured and the Vercel route has an edge or durable per-client rate limit. The local server applies an in-memory rate limit, which does not protect a scaled serverless deployment.
